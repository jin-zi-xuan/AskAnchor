# 锚点定位修复与验证

这次沿着原来的定位方案修复，没有改追问流程和平台配置。

## 改了什么

- 从原文节点向上找滚动容器，不再用屏幕边缘的元素猜测。
- 多行、跨段选区以首行作为阅读落点，同时处理内外两层滚动。
- 平滑滚动后检查原文坐标，最多纠偏 4 次，总等待不超过约 1.6 秒。只有原文仍然存在且落点核验通过后，才恢复精确高亮。
- 用户滚轮、触摸、指针操作、滚动按键、切换对话或点击另一个锚点时，中止旧的自动定位。
- 保存滚动容器的定位信息和各层滚动值，刷新后分别恢复；无法识别的旧嵌套记录不会误报恢复成功。
- 修正整段选中时的元素边界偏移，避免把结束位置算成 `-1`，导致锚点缺少文字定位信息。
- 段落里新增相同文字时，允许在已确认的回答内通过前后文重新定位；若有多个可信结果，仍然降级，不猜某一次。

## 怎么复查

安装项目依赖后运行：

```sh
npm test
npm run test:browser
```

浏览器测试使用 Playwright 启动已安装的 Google Chrome，创建独立上下文。页面内容来自本地测试夹具，对聊天站点地址的请求被测试拦截，不会连接真实聊天服务，也不读取现有浏览器登录状态。可以通过环境变量 `BROWSER_CHANNEL` 选择其他已安装的兼容浏览器通道。

浏览器回归覆盖：屏幕外原文、整页滚动、嵌套滚动、嵌套位置恢复、整段选区保存、长选区首行、布局变化、用户取消、目标移除、连续跳转、重复文本消歧，以及加载全部生产内容脚本后的“保存—重载—点击列表—原文高亮”流程。

## 验证范围

本地真实 Chrome 的几何定位和完整内容脚本入口已验证。测试不等同于逐个验证所有在线 AI 平台的最新页面结构。

未加载到 DOM 的历史消息仍可能需要平台先加载出来；持续超过纠偏窗口的布局变化也可能影响最终位置。这次没有增加自动遍历整个长对话的加载流程。

以前缺少有效选区信息的锚点不能凭空补回原始偏移，仍会尝试现有恢复路径，失败时保留原文卡片。新增锚点会保存修复后的信息。

修改后需要在扩展管理页重新加载 AskAnchor，再刷新使用它的 AI 页面。
